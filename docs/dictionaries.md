# 词库格式与加载规则

AutoTyper 使用本地 YAML 词库进行中文拆词，并可读取词频影响输入节奏。

## 文件发现

词库文件必须命名为：

```text
*_words.yaml
```

程序只搜索一个位置：

- 可执行文件所在目录。

多份词库会自动合并。文件发现逻辑位于 `src/typing/word_files.rs`。项目根目录、当前运行目录和 `data/` 不会被额外扫描。

## YAML 格式

当前兼容两种格式。

旧格式：

```yaml
words:
  - "自动输入"
  - "雨课堂"
```

带词频格式：

```yaml
words:
  - text: "自动输入"
    frequency: 12345
  - text: "雨课堂"
    frequency: 678
```

解析逻辑位于 `src/typing/yaml_words.rs`。

## 合并规则

合并逻辑位于 `src/typing/dictionary.rs`。

- 词条文本相同则视为同一个词。
- 如果多份词库都有词频，保留更高的 `frequency`。
- 没有词频的词仍可用于拆词和错字候选，但不参与词频速度调整。
- 错字模拟使用合并后的词条文本作为候选池，词频不影响候选选择。
- 程序会先加载内置词，再合并外部词库；没有外部词库时仅使用内置词。

## 内置词库

内置词库由两部分组成：

- `src/typing/common_words.rs` 中的项目专用词。
- `data/jieba_builtin_words.tsv` 中从 jieba 词库挑选的 1000 个日常高频中文词。

`jieba_builtin_words.tsv` 使用制表符分隔：

```text
词<TAB>词频
```

这些词始终会参与拆词、错字候选和词频速度计算；外部 `*_words.yaml` 会在其基础上合并。第三方来源说明见根目录 `README.md` 末尾。

## 错字模拟用途

错字模拟不会读取额外的错误词库，而是复用当前合并后的词库文本。`src/typing/dictionary_typo.rs` 会把每个词的非完整前缀加入索引；查询某个中文词时，从最短前缀开始找共享前缀的其他词，找到后用稳定抖动选出一个候选。

因此，外部 `*_words.yaml` 越贴近用户真实输入场景，中文错字候选也会越自然。词频只影响输入节奏，不影响错字候选选择。

## 雾凇词库

当前根目录的 `rime_ice_words.yaml` 是雾凇拼音词库裁剪后的本地版本，只保留拆词所需的 `text` 和 `frequency`。程序不会额外扫描项目根目录；如果要让发布后的二进制加载这份词库，需要把它放到可执行文件同目录。

本项目不保留：

- 上游完整仓库。
- 临时下载脚本。
- 原始 `.dict.yaml` 文件。
- 拼音编码列。

这符合“不要内置外挂，只保留本地词库数据”的约束。

## 词频用途

词频不会影响拆词命中顺序。拆词仍然是最长匹配优先。

词频只影响输入速度：

```text
最终中文词组预算 = 基础词长预算 * 词频后置倍率
```

词频越高越接近 `1.0x`，词频越低越慢。

## 修改建议

- 要支持新 YAML 字段：改 `yaml_words.rs`。
- 要改变多词库合并策略：改 `dictionary.rs` 的合并逻辑。
- 要改变词库搜索位置：改 `word_files.rs`；默认不要恢复项目根目录或当前运行目录扫描。
- 要改变词频如何影响速度：改 `frequency.rs` 和 `timing.rs`。
- 要改变错字候选规则：改 `dictionary_typo.rs` 和 `typo.rs`。

## 注意事项

- `rime_ice_words.yaml` 很大，编辑时尽量使用脚本或流式工具。
- 不要把词库解析写成依赖固定行号或固定排序。
- 保持旧格式兼容，避免用户已有 `*_words.yaml` 失效。
